为什么我先学 F103 而不是 F407

2026-09-16·约 6 分钟· STM32F103C8T6 vs STM32F4
Note Written in Chinese; the comparison table is language-neutral. Happy to discuss the reasoning in English.
先把话说在前面 两块板子我都没用过。所以这一篇不是「经验帖」，而是我买之前的选型笔记：依据是 ST 官方产品页与数据手册、以及我实际面临的约束（预算、磁盘空间、学习目标）。我把依据写出来，如果你觉得哪条判断错了，直接告我，我改。

一、先摆约束，再谈选型

选型从来不是「哪个芯片强」，而是「在什么约束下，哪个更值得先学」。我的约束是三条：

  • 预算：入门全套想在 ¥100 以内解决（最小系统板 + 下载器 + 面包板 + 外设）。
  • 磁盘：我这台电脑 C 盘只剩 3 GB。Keil MDK 装完约 1.5 GB，CubeMX 还要装 Java 环境、加起来约 1 GB——这是必须先解决的问题，也直接影响我能用多重的工具链。
  • 目标：这个阶段我要的是把外设原理打通（GPIO / 定时器 / PWM / 串口 / I²C / ADC），不是马上把一台车跑起来。

三、我为什么先用 F103

  1. 海报要求的外设，它一个都不缺。GPIO、定时器/PWM、串口、I²C、ADC、外部中断——F103 全都有。学外设原理和学「更强的芯片」是两件事：Kp/Ki/Kd 的意义不会因为在 168 MHz 的芯片上跑就变，时钟树怎么算、ARR/CCR 怎么定、I²C 起始条件怎么发，这些在两个系列上是一模一样的知识。
  2. 外设的编程模型可以平移。两个系列都用 ST 的 HAL 库，函数名与结构（HAL_GPIO_Init / HAL_TIM_PWM_Start / HAL_UART_Transmit …）基本一致，CubeMX 的配置界面也是同一套逻辑。所以「先用 F103 打基础」不是绕路，之后迁移的成本主要在参数和外设数量上，不在概念上。
  3. 出错时更容易找到原因。F103 的资料密度最高，遇到问题（比如时钟树配错、串口乱码、I²C 卡住）时更容易找到同款问题的排查过程。入门阶段最大的成本不是芯片价格，是卡住的时间。
  4. 它便宜到可以「不怕烧」。¥15 的板子坏了再买一块就是。这一点对新手挺重要——我希望能放心地把杜邦线插错、把电源接反一次，而不是每接一根线都怕弄坏几百块的开发板。

四、代价我也写清楚

  • 没有 FPU：所有 float 运算走软件浮点库，比 F4 慢很多。这也是我在 pid.h 里特意用 float 而不是 double 的原因——在 Cortex-M3 上 double 的运算量还要再翻一倍。
  • RAM 只有 20 KB：不能随便开大数组。
  • CAN 只有 1 路，定时器数量也更少。如果目标直接是「一台能上赛场的车」，F103 是不够的——那时候该直接上 F4。
  • 主频低：高频率的控制环（比如电流环跑 10 kHz 以上）在它上面会吃紧。

五、什么情况下我会直接选 F4

如果我的目标是「两个月内做出一台能跑的整车」，那正确的做法是直接上 F4——因为 CAN 电机、功率控制、多路外设并发这些事，在 F103 上做不了或者做得很难受。

但我的现状是「零硬件经验、要先把原理弄懂」，所以我把顺序定成：先用 F103 把外设和电路基础打通 → 再学到 F4（外设模型直接平移）→ 进队之后上真实车。这个顺序的代价只是多花 ¥15 和一段时间，换来的是每一步都能自己讲清楚。

这条「先便宜板子、后迁移」的思路，代价是什么 代价是：我现在还不能直接上手战队的主力平台。这一点我在主页的短板清单里也写了。我选择接受这个代价，因为比起「拿着一块 F4 却讲不清时钟树」，我更想先把原理讲得清楚。
